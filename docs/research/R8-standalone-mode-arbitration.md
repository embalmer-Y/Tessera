# R8 · standalone 运行模式与控制源仲裁调研（DEC-56 · R 批③）——合同泛化批设计输入

> **日期**：2026-10-13 · **触发**：DEC-56 D6（设备独立运行与远程编排同为一级模式；断链 fail-safe 语义声明化；本地控制源入仲裁模型；estop 至高不变）· **消费方**：合同泛化批 design（**门④——安全合同修订**）。
> **方法**：web 实抓（IEC 61508-4 / ISO 13850 / EN 60204-1 / ISO 10218 / ISO 17757 / Beckhoff EtherCAT / ROS 2 lifecycle 与 ros2_control / HOA 惯例——来源见 §7，原文抓取与二手来源逐条标注）+ 本地事实（安全合同十条 / DEC-22 断链参数 / DEC-41 租约）。
> **结论先行**：① 现合同的**逐通道三安全态声明**（合同 1）与消防风闸"失效值按负载语义逐台定义"同型——地基正确，无需推翻；② 泛化方向有直接工业先例：**EtherCAT SM watchdog 按通道替代值**（失联行为可按通道配置替代值/斜坡/保持末值）与 **ISO 17757**（自治机器须在任何通信失效下维持安全运行 = "失联≠故障"的明文背书）；③ 本地优先有明文：**EN 60204-1 §9.2.4「便携/无线站激活时，运动只能自该站引发」** + HOA 现场惯例（Hand 位压制 SCADA）；④ **estop 复位的工业规范 = 仅本地**（ISO 13850：复位须由急停器件本身脱开，不许远程复位）——我们现行远程 estop-clear（confirm 令牌）对 standalone 设备构成设计张力，须在合同泛化批裁决；⑤ 模式切换本身不得引发输出（§9.2.3）与无扰切换（bumpless transfer）为切换语义提供两条约束/技法。

## 1. 现状与泛化对象（本地合同事实）

| 合同/机制 | 现语义 | standalone 泛化问题 |
|---|---|---|
| 合同 1 三安全态 | 每通道声明上电/断链/故障态值 | 地基与先例同型（§2.4）——**不变** |
| 合同 3 断链 fail-safe | linkmon 心跳丢失 → 全输出进 SAFE_LINKLOSS | standalone 无编排者在场，断链≠故障（ISO 17757 背书）——**触发语义需按部署模式声明** |
| 合同 5 estop | 硬件 ISR 至高 + 事后补发；清除 = 远程命令 confirm="estop" | ISO 13850 = 复位仅本地人为——**清除通道需按设备形态裁决**（本地交互面 / 保留远程带令牌 / 双通道） |
| DEC-41 租约 | 网络侧单租约仲裁写命令 | 本地交互 = 无席位——**仲裁模型扩席** |
| DEC-22 断链参数 | 心跳 1000ms/丢失 6（prov 可配） | 参数随模式语义联动重审（数值面窄） |

## 2. 工业先例 → Tessera 映射

### 2.1 安全状态与失效值（合同 1 的外部印证）
- IEC 61508-4：safe state = EUC 达到安全时的状态；危险态→安全态**可经中间态**；安全功能声明需求模式（低/高/连续——连续模式 = 持续保持安全态）。→ 我们的连续控制类 APP 正属"连续模式"，安全态是持续维持的对象而非一次性到达。
- 消防风闸：防火分割闸 fail-closed（弹簧保持屏障）、排烟阀可 fail-open——**失电安全值按负载语义逐设备定义，非全局一刀切**。与我们"每通道三态显式声明"同型（合同 1 地基正确）。

### 2.2 失联行为（合同 3 泛化的直接先例）
- **Beckhoff EtherCAT SM watchdog**：超时 → 输出走 substitute value（0x80n0:13），Watchdog Type 可选替代值/斜坡/保持末值；**替代值按通道配置**、超时时间整机级。→ 映射：我们已有逐通道 linkloss 态值；泛化 = **触发条件按部署模式声明**（orchestrated：心跳丢失触发〔现行〕；standalone：无编排心跳预期，断链不触发状态迁移，仅事件留痕）。
- **ISO 17757:2019**（自治机器系统）：要求在任何通信类失效下维持安全运行——"断联≠故障"的明文背书（安全态由风险评估定义，停车挡道亦是隐患的例子直接对应"standalone 温控断网停控是错的"）。

### 2.3 控制源仲裁（租约模型扩席的先例）
- **EN 60204-1 §9.2.4（明文）**：「便携式/无线操作站在激活时，运动只能自该站引发」——本地站激活 = 压制远程，直译为我们需要的"本地优先"语义。
- **HOA 惯例**（Rockwell PowerFlex / Honeywell HC900）：Hand 位本地启停压制远程 SCADA、Off 隔离、Auto 交还系统——**本地物理位高于远程调度**的现场共识；HC900 含 BYPASS 态（旁路本地）。
- **ros2_control**：command interface 独占 claim（state 可共享），switch_controller 以 STRICT/BEST_EFFORT 先解冲突持有者再授权——与 DEC-41 单租约同型，扩席 = claim 主体集合加"本地源"。
- **无扰切换**（bumpless transfer）：手动态输出被反算跟踪，切自动无阶跃；反向由手动站自当前输出初始化——控制权交接时输出连续性的技法（合同泛化批的交接语义参考；V1 可先"交接=重声明"简化，如实登记差距）。

### 2.4 estop 复位（合同 5 的张力点——须裁决）
- **ISO 13850:2015**：复位「须由急停器件本身的脱开来执行」（旋钮/拉拔/钥匙 = 本地人为动作）；**复位不得引发再启动**（须另行启动）；急停态锁存至本地复位 = **不允许远程复位**。
- 现行：固件 estop-clear = 远程 zenoh 命令 + confirm 硬令牌（LLD-ts-net §4）。
- **张力定性**：远程清除对无头编排部署（现状 S3 bench）是工作必需；对有本地交互面的 standalone 设备，工业规范是本地复位。→ Q-41 子项：清除通道按设备能力声明（无本地交互 = 远程带令牌维持；有本地交互 = 本地清除为主、远程清除可禁用/降级）。estop **触发**面（硬件 ISR 至高）双方一致，不动。

### 2.5 模式切换约束（§9.2.3）
- 「运行模式选择本身不得引发任何机器运行，须有单独的启动控制」——映射：部署模式/控制权切换**只改仲裁，不直接产生输出**（防"切模式带出动作"类缺陷）；防未授权 = 钥匙/访问码形态（本地交互设备的物理/口令门）。

## 3. 建议的合同泛化形态（Q-41 呈递主体——门④，本文只定方向）

1. **部署模式声明**（prov 扩展，DEC-22 邻位）：`orchestrated`（现行语义不变——被编排端点失联进安全态）| `standalone`（断链不触发迁移；看门狗/estop/限幅等本地合同全量生效）| （混合形态——按通道组声明——留 design 评估是否 V1 需要）。
2. **控制源席位**：仲裁主体集合 = {zenoh 命令（租约）, 本地交互源（设备外设事实——有则占席）, estop（至高，席外）}；本地源激活时按 EN 60204-1 §9.2.4 压制远程写命令（机制：租约模型加"本地持有"态或写命令门控位）；切换只改仲裁不产生输出。
3. **estop 清除通道**：按设备能力声明（§2.4）；复位不引发输出 = 与现行"清除后显式 commit 恢复"语义已一致（estopbench 先例）。
4. **合同文本不改弱**：十条合同的本体不动，泛化 = 新增"部署模式"条目 + 合同 3 的模式化表述修订（门④呈递措辞随 design 批）。
