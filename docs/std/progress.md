# 项目进度记录规范（progress.md）· v0.1 草案

> **状态**：v0.1 草案，随规范套件待 owner review（见 `README.md`）。
> **目的**：把"项目当前在哪、下一步是什么、谁裁了什么"变成任何人（含无会话上下文的 AI/人）读文件即可回答的状态。

## 1. 事实源（单一职责，互不重复）

| 事实 | 唯一事实源 | 更新时机 |
|---|---|---|
| 项目当前状态 / 待办 / 禁区 | `AGENTS.md` §1 当前状态 | 每会话结束前（必做） |
| 裁决与待裁问题 | `decisions.md` | 裁决发生 / 新 Q 登记 |
| 命名空间 | `docs/names.md` | 新标识符诞生 |
| 设计规格 | `design/*.md`（含各自修订记录） | design 阶段 |
| 交付与历史 | `git log` / tag | 每交付单元一提交 |
| 调研事实 | `docs/research/*.md` | research 阶段 |

- **聊天与记忆不是项目状态**（军规 8）：会话中的结论若不落上述文件，视为未发生。
- 禁止在多处维护同一事实（复制即漂移）；引用用链接（如"见 DEC-17"）。

## 2. 会话协议（AI 开发协作规则）

1. **会话开始**：按 `AGENTS.md` §2 bootstrap（当前状态 → 未裁 Q → 本阶段文档）；上下文被压缩后以文件为准续写。
2. **会话中**：一个会话一个可验证交付单元（军规 §2.3）；超出登记待办另起会话；owner 当场指令的例外照办并在交付报告中注明。
3. **会话结束**：执行 `AGENTS.md` §9 检查单（提交 / 落盘 / 命名登记 / 状态更新 / review 门呈报）。
4. **子代理**：提示词自包含；`AGENTS.md`/`decisions.md`/`design/` 修改权只在主会话。

## 3. "当前状态"节格式（AGENTS.md §1 的书写规范）

```text
- <日期> · <一句话状态：阶段 + 门位置>
  - 交付物：<文件/commit/tag 清单>
  - 待办：① …（编号列表，可溯到里程碑）
  - 门状态：<哪个 review 门开着，等 owner 什么输入>
```

- 待办项必须可执行（"优化 XX"不合格；"M0：west init + native_sim 空模块"合格）。
- 前一会话条目**保留**（追加式，不改写历史状态）；超过 5 条时可归档最旧条目到本文末尾附录。

## 4. 里程碑与进度登记

- 里程碑（M0/M1/M2/M3…）在 `docs/names.md` §2 登记；定义与 DoD 在 `design/HLD-firmware-framework.md` §7。
- **退出**：对照 DoD 逐项打勾 → 停 review 门（§2.4-②）→ owner 通过 → 打 tag `m<编号>` → `AGENTS.md` 状态更新。
- **延误/阻塞**：在当前状态"待办"中标注阻塞原因与所需裁决；不静默延期。
- 失败与回退：以 `fix:`/`revert` 提交留痕 + 状态节一句话说明（禁改写历史，军规 5）。

## 5. owner 裁决的接收与登记

- owner 回复（含口头/简洁表述）由主会话按生命周期登记：Q-xx → DEC-xx，附日期与**原文逐字**；语义规范化表述写入决策列，原文不可省（可溯）。
- 裁决语义有歧义时，登记时以"解读 + 歧义点"呈报 owner 复核，不自裁。
