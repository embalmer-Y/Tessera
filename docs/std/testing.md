## 1. 测试层级

| 层 | 名称 | 平台/工具 | 跑点 | 强制性 |
|---|---|---|---|---|
| L1 | 单元测试 | ztest，native_sim | 每次提交（CI） | 必须，与实现同批（军规 7） |
| L2 | 子系统测试 | ztest/自定义 harness，native_sim | CI | 涉及多模块协作的交付必须 |
| L3 | 系统集成 | native_sim 全框架 + 外设桩 | CI + 里程碑 | M2 起必须 |
| L4 | 确定性重放 | 重放框架（虚拟时钟注入） | CI | 涉及控制/调理链的交付必须 |
| L5 | 安全合同机械检查 | 静态扫描脚本（见 §3） | CI，独立 job | **永远必须，违反即失败** |
| L6 | 硬件在环 | 四板真机 | V1 后期 | V1 非门槛（DEC-13） |
| L7 | PC 侧测试 | pytest（Agent/模拟器/工具链） | CI | 第二阶段（DEC-15）起必须 |

## 2. 确定性重放测试（合同 9 的机械验证）

- **方法**：输入序列文件（含虚拟时间戳）→ 系统执行 → 输出序列（含驱动落点与时间）→ 与 golden 文件**逐位比较**。
- **规则**：
  - 时间一律经虚拟时钟注入（`ts_time_ms()` 在测试构建下替换为受控源）；禁真实墙钟参与断言。
  - golden 文件变更必须说明来源（预期行为变化 = 规格变化，须对应 design 修订记录或 Q 裁决），禁止"跑一遍拿输出当基准"式更新。
  - 必测场景基线：断链→安全态→恢复；estop→SAFE_FAULT；WDT 超时；APP 健康探针超时→回滚；初始化逐步注错（每一步失败都进 fail-safe）。

## 3. 安全合同机械检查（L5，CI 独立 job，一票否决）

1. **唯一写路径**：全库扫描 Zephyr 输出驱动调用（`gpio_pin_set`、`pwm_set_*` 等清单由 ts-safety 维护）；合法出现点白名单 = `ts-safety` 出口文件。白名单外出现 = 失败。
2. **三安全态注册完备**：输出/供电通道注册必须带三态声明（注册 API 类型强制 + 静态扫描描述符表）。
3. **禁用模式扫描**：控制路径禁未播种随机（`rand`/`random`）、禁墙钟（`k_time`/`time()`/RTC 直读）、禁容器迭代序依赖（审查项，脚本查 `FOREACH` 族宏的使用清单）；发现即失败，豁免须登记 Q。
4. **常量出处**：可调常量（限值/超时/尺寸）旁注释必须含 `DEC-xx` / `Q-xx` / 推导链接三者之一；无出处 = 失败（配合 `coding.md` §4）。
5. **estop 路径**：estop ISR 调用图中禁出现分配/队列/协议栈符号（脚本按符号表检查）。

## 4. 覆盖率门槛（默认值，待套件生效裁决）

| 范围 | 行覆盖 | 说明 |
|---|---|---|
| ts-safety / ts-appmgr | ≥ 85% | 安全与权限强制点 |
| 其余固件模块 | ≥ 60% | |
| 机械检查脚本自身（L5 工具） | ≥ 80% | 工具不可靠则检查不可信 |

- 统计基于 native_sim gcov；门槛外的合理豁免（如硬件相关性代码）逐条注释并计入交付报告，禁止批量豁免。

## 5. 测试与交付的绑定

- **同批原则**（军规 7）：实现 commit 必须含对应测试；只带实现的提交 = 流程缺陷，review 拒收。
- **失败处理**：失败如实报告（禁止美化、禁止把失败改写为"选择不行动"）；失败修复后补测留痕。
- **flaky 用例**：出现即登记（隔离清单 + 对应 issue/待办），两周内修复或删除；隔离清单在 CI 报告中显式可见。
- **skip 纪律**：`skip` 必须带原因注释与恢复条件；无注 skip = 失败。
- **DoD 口径**：CI 全绿（含 L5）+ lint 通过 + 新增/变更测试同批，才可声明交付完成；有缺口如实列出（军规 10）。

## 6. CI 布局（与 M0 骨架对应）

- 触发：每次 push / PR；里程碑 tag 额外跑全量 + 产物构建。
- job 顺序：lint → L5 机械检查 → 构建（native_sim）→ L1/L2 → L3/L4 → 覆盖率汇总。
- 平台基线：native_sim（DEC-13/14）；四板真机构建验证（不上测试）进 CI 可选 job。
