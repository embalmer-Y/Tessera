## 7. 已知缺陷登记：native_sim/native/64 的 wasm APP 执行路径（WAMR 64 位目标域）
症状：framework.app / framework.threads 全部「完整运行 wasm APP→GPIO 事件」用例失败。
X86_64（及 AARCH64）目标：APP 线程首个 native 调用即 SIGSEGV（rc=-11，twister 16 blocked）。
X86_32 目标（旧映射）：不崩但 APP 写静默不落地（wait_gpio 6s 超时，APP 自身日志行正常）。
gdb 回溯（两目标完全同签名，垃圾指针为同一常数 0xaa0803f0a9467bfd）：
  #0 ts_app_rt_ctx (r=0xaa0803f0a9467bfd) runtime.c:94        ← exec_env user_data 槽 = 陈旧垃圾
  #1 ctx_of(env) natives.c:33
  #2 native_gpio_write natives.c:40
  #3 wasm_runtime_invoke_native wasm_runtime_common.c:6155   ← WAMR 通用 invoke 路径
     （该函数按 BUILD_TARGET 分支：X86_32 = 参数紧排 / 其余 = 8 字节对齐双字排布——
       X86_32 模型在 64 位 ARM 宿主上结构性不成立）
域定性：WAMR 2.4.5 通用 invoke-native × 64 位目标 × aarch64 宿主——32 位 CI 口径不受影响；
根治路径候选（后续专项）：a) /64 改用 AARCH64 目标 + 对应架构 invoke thunk（AARCH64 目标实测亦崩，须先解
  exec_env user_data 槽污染——疑 INVOKE_NATIVE_GENERAL 路径 64 位布局缺陷）；b) 上游 issue；
  c) APP 线程 exec_env 改 spawn_exec_env 专槽（WAMR 单线程-单 env 纪律——app 主线程现直接复用 r->env）。
本会话定版：CMake /64 映射 = X86_64（诚实崩溃优于静默错）；twister /64 通过线 = 14/16 套件。

## 8. 「接入 ARM 机后随机重启」破案与处置（2026-10-17 11:31-11:43，owner 报障触发）

现象：板接入 ARM 机后随机时间重启。console 监听（教训 38 纪律 holder，DTR/RTS 双 deassert）抓到完整循环：

  boot(~45s bench 自检) → WiFi rc=0 → net 起 → mTLS 注入 → zenoh_open rc=-102
  loc=tls/192.168.2.91:9956（**prov 指向 x86 时代死路由**）→ 无退避立即重试再注入
  → NET 域喂狗饿死 → 巡检 WDT_WARN → ts_safety_system_fail(TS_FAIL_WDT(net))
  → noinit 留痕 reason=0x00020000 → 受控停机 → rst:0xc (RTC_SW_CPU_RST)
  → 周期 ~50s 复位循环

判别排除：宿主域无罪——无进程持口（ModemManager/brltty inactive）、USB autosuspend=off、
内核 USB 枚举仅插拔一次、复位原因非 BROWNOUT 非 POWERON 非 EN 脉冲。
域定性：**固件健壮性缺陷（F1 家族新形态）+ 环境错配叠加**——prov 所指路由器随 x86 销毁死亡；
TLS 重连路径无退避且在握手段不喂 NET 狗（x86 时代路由常活未暴露；无路由器场景从未设防）。

处置（重 provision，不动镜像——WiFi 凭据保持板上现值）：
  ① tools/board/gen_tls_certs.sh ~/project/tls 192.168.2.101（旧链随 x86 不可恢复，重签；
     SAN = ARM 机 IP）
  ② zenohd TLS mTLS 双监听 9956/9957（本机常驻）
  ③ fuser -k 清隐残留持有进程（TaskStop 只杀外层 shell 的现实重现）→
     esptool erase_region 0x5f0000 0x1000（教训 33；prov 分区 4KB @0x5f0000）→
     flash_prov --node akn --cube akc --router tls/192.168.2.101:9956
     --pub0 ts-test-root.pub --lconf 1 --tls-{ca,cert,key} 新链 DER（教训 39 末步）
结果：**CONNECTED loc=tls/192.168.2.101:9956 → AK PASS → 连续 233s+ 零复位**
（对照：旧循环同窗必复位 5-6 次），alive 心跳 net=1 每 10s，路由器侧 TLS 会话建立。

登记（后续专项候选）：无路由器场景应降级 fail-safe 常驻而非复位循环——
  TLS 重连加退避 + 握手段喂狗（或 WDT 窗口豁免），固件健壮性批次处置。
注：zenohd TLS 实例随本会话存活；持久化（systemd 用户单元）待 owner 点向。

## 11. §7 缺陷根治追记（2026-10-18，DEC-64④/R3）
root cause = GENERAL C invokeNative thunk × 64 位寄存器分类路径契约错配
（GENERAL=1 为 ia32 汇编 GNU-stack 规避所设；64 位 branch C 的 fps/ints/stacks
三桶布局下小签名 n_stacks=0 → GENERAL switch(argc) 收 0 → 零参数调用 native →
exec_env 形参 = 寄存器残留 = 常数垃圾）。修复 = /64 按宿主映射 AARCH64/X86_64 +
真实架构汇编 thunk（GENERAL=0 + -Wa,--noexecstack）。
判据：twister native_sim/native/64 **16/16 套件 114/114 用例首次全绿**
（framework.app/threads 收口）；32 位 x86 CI 口径不变。详见 DEC-64④。
