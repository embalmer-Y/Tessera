== 供电评估（owner「评估供电是否足够」）==
静态：hub lsusb = Terminus 1a40:0101 **Self Powered**（外接供电形态，下游口
USB2 标准 500mA/口）；dmesg 过流事件 = 0（双板部署带载全程复查仍为 0）。
带载实证：双板 WiFi 同网 + Agent 部署分块突发 + LN 扇出全程——两板串口
**零 brownout、零 WDT、零异常复位**（/tmp/bv2_dual_serial.log 双串口并行实抓）。
结论：供电充足（实测口径）。

== 板身份实测（esptool flash-id）==
atk：ESP32-S3 Dual Core 240MHz + PSRAM 8MB（AP_3v3 OCT）+ **boya 16MB
（JEDEC 68:4018——与一四三档案全同）**。Zephyr 板名 dnesp32s3b（树内
alientek/dnesp32s3b 收录——BV2 收录板路）。

== BV2 流水线（生成件 = 板级面唯一来源，零手写板级件）==
adapt_included_board(dnesp32s3b, 16384KB, xtensa, psram=oct, pwm_led_pin=4)
→ agent/adapt/dnesp32s3b/{board.overlay, board.conf, prov.json, workorder.json}
  · 分区 = 16384 模板（prov 0x7e0000/meta 0x7e1000/slot 32KB×2/noinit——P4 同族）
  · overlay 含 &wifi 使能 + LEDC_CH0_GPIO4 PWM 绑定 + zephyr_user pwm-uid
  · conf 含 SPIRAM OCT 家族 + R1/R2 4096 + xtensa main 栈 8192（教训 31⑤）
C0 预检 OK → deploybench 构建（-DEXTRA_DTC_OVERLAY_FILE/-DEXTRA_CONF_FILE
指向生成件；凭据 /tmp cmake -C 注入）：
  第一轮 FAIL：dram0 溢出 25164B——MP 每板预算纪律实测敲定 heap 131072→98304
  （产物内注记推导；xiao 基线值携其板级裁剪语境）
  第二轮 PASS：787KB 镜像，**板级面 100% 出自 BV2 生成件**

== 实战回填生成器的三缺口（首实战价值，随批入仓）==
1. esp32s3 板 &wifi 节点缺省 disabled——模板按 soc 分派使能行；
2. PWM 硬依赖 bench（deploybench main.c 无桩符号）——模板 pwm_led_pin
   参数（调用方板级硬件事实，HW-4 source 纪律）→ conf PWM 面 + overlay
   ledc/pinctrl/zephyr_user 绑定；
3. 网络内存家族（R1/R2 4096 + xtensa main 8192 + PSRAM 卸载家族）——
   net 模板恒开。
另有 prov 陈旧路由修复：deploybench 内嵌 prov = x86 时代 tcp/192.168.2.91:9955
→ 重生成（cbor2 确定性编码，键序/结构逐字段对拍原 blob，仅路由串 21→22 字符）。
