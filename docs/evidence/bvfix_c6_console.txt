板级部署崩机专项修复证据（2026-10-19 · V0.13.0 FIX-1）
=======================================================
问题（BV1-R C6 阻断位）：部署分块突发 → esp32_wifi_adapter ENOMEM →
rx_q[0] 栈溢出 FATAL 崩机（NET_RX_STACK_SIZE 缺省 1500B）——确定性复现。

== 修复链（三轮构建对照 + prov 复原 + agent 自愈）==
B1  STATIC_TX + SPIRAM heap + rx4096 → 关联活但数据面死（RX DMA 缓冲入
    PSRAM → DHCP 不可达 → z_open -102 循环）——SPIRAM heap 撤回
B2  STATIC_TX + rx4096 → WiFi 关联直接失败 rc=-134——STATIC TX 撤回
    （4.5-rc1 驱动/hal 双层 TX buffer Kconfig 映射存疑——登记待上游核实）
B3  仅 rx4096（NET_RX_STACK_SIZE 1500→4096）→ **崩机根治**（多轮部署零
    FATAL）+ C4 恢复 PASS（反证 STATIC TX 为关联杀手）
prov：lconf 1→0 复原（F3 实验残留安装闸挡激活——flash_prov 既有路径；
    pub0 = ts-test-root 32B raw + TLS 三元组 + offset 0x5f0000 纪律）
agent：push_app 分块路径租约瞬断自愈——「lease required」= 板侧执行器
    高压停顿（wifi TX 拥塞窗）> 租约 TTL（10s）懒过期；force renew 后
    同 idem 重发（幂等安全）；两轮真机验证自愈有效

== 判决（atk-dnesp32s3b 全链验收跑）==
C1 串口在场      PASS
C2 flash 身份    PASS（chip=ESP32-S3 size=16384KB boya 16MB）
C3 boot/console  PASS（CONNECTED loc= 命中）
C4 zenoh 连通    PASS（akn/akc 命令面回执全通）
C5 caps 消费     PASS（tiers=[small,large] slot_pool=2048KB）
C6 部署 E2E 冒烟 PASS（deploy + 判据 'd9 init' 命中，103.4s）
overall = PASS（rc=0）；此前 C4+C6 两轮连 PASS（96.2s / 115.1s）

== 内存落位（map 对照）==
dram0：384.4KB → 386.5KB（仅 rx 栈 +2.1KB）；静态 TX 缓冲若走 DRAM 将
+26KB——未发生（B1/B2 撤回后 TX 维持 DYNAMIC；wifi 堆维持 DRAM 系统堆）
DRAM 静态区余量仍薄（~12KB）——map 重平专项维持登记（wifi ENOMEM 噪声
未绝，仅崩机根治）

== 残余登记 ==

   map 驱动重平专项存续
