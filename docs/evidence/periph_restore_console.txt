外设三路失败破案 + 板态复原证据（periph_restore_console.txt · 2026-10-17）

1. 事件：2026-10-17 晨 HEAD 镜像（console=USJ）boot 三路外设同败——
   [es8311] no chip @0x18 / AKa0 es8311 init rc=-2
   AK WARN sd mount r=-5
   AKU1 LCD+LVGL init rc=-5
   当日登记为「疑重插后接触不良，待 owner 物理复查」。owner 复核反馈：
   SD 卡已重新格式化、板载芯片为焊接（连接面无虞）——物理接触假说排除。

2. 判别：git worktree @ 61d9c9f（F3-1，外设最后全绿提交）全新构建 →
   F3-1 树在现板不可直接判别（16M 布局镜像 + console=uart0——app 输出不可见）。
   转真值探针路线：console 临时切 uart0 经 CH343（ ROM 下载协议已实证该
   数据路物理可用）→ 同一构建配置族首次拿到全量启动输出。

3. 复原判据（同族配置 boot 全绿——证据 /tmp 采集于 2026-10-17 14:0x，原始
   留痕 ~/project/logs/periph_restore_console_raw_20261017.txt）：
   [es8311] init: fs=16000 bclk=1024000 slot=32bit ring=4x1280B addr=0x18
   AKa0 es8311 init rc=0            ← I2C0 通（晨间 no chip 消失）
   AK7 SD mounted（/SD:/res 就绪）   ← SD 通（owner 重格后介质态正常）
   AKU1 LCD+LVGL init rc=0          ← LCD 通（XL9555 背光 I2C0 路随通）
   连续两次 boot 复现全绿。

4. 结论（三路失败根因定性）：
   - es8311 + LCD = I2C0 总线域板态（疑似总线锁死——S3 复位不锁存、上电
     序列解开；与 89cee3e~5cc02d4 构建内容无因果——同族配置全绿证伪配置回归）。
   - SD = 卡介质态（owner 重格即愈——独立于 I2C 域）。
   - 「重插致接触不良」与「TLS 批配置回归」两假说均证伪；SKIP_PERIPH_FAIL
     旗标保留（默认构建语义未变，外设失联降级用途仍成立）。

5. 顺带事实（本批四项登记）：
   a. flash 真硅二次勘误：bootloader 实报 "detected chip: boya" +
      "Detected size(16384k) larger than the size in the binary image
      header(8192k)" + esptool JEDEC Manufacturer=0x68 Device=0x4018
      —— **boya 16MB**（v2.25「gd 8MB」登记翻案；8MB 布局兼容续用——
      分区全部 <8MB，仅用下半）。
   b. uart0/CH343 打印路可用（本证据即 uart0 console 全量 boot log）——
      教训 38「uart0 通路不通」修正；console 与烧录口可解耦（CH343=
      console+esptool+EN 复位三功能）。
   c. prov 覆盖陷阱：TLS prov（tls/…:9956 locator）被后续镜像的
      prov-write-test 兜底路径以编译内测试 blob（tcp/…:9955）静默覆盖
      （load fail → burn 测试 blob）——表症 = mTLS 注入行消失 + zenoh
      TCP 9955 恒 -102。复烧 15 对 TLS prov（flash_prov --tls-* 三元组 +
      tls/ locator + --lconf 1，offset 0x5f0000）即愈。
   d. USJ 宿主枚举闩死：hub 端口 1-7.2 无设备声明（ROM 下载态亦不枚举；
      hub authorized 翻转 + uhubctl 端口电源周期均不复活）——线缆/板侧
      USJ 域，owner 重插 USJ 线缆即判。CH343 全功能替补期间不阻塞。

6. 复原终态（prov 重烧后同 boot）：
   [ts-net] tls: mTLS 注入 ca=398B cert=391B key=138B（名称校验 ON）
   [ts-net] zenoh_open: CONNECTED loc=tls/192.168.2.91:9956
   zenoh 命令面回执（get-info 39B 结构化应答经 9957 TCP → 路由 → 9956
   TLS 板端全环）——板回到 P1-2 E2E 收口态，三外设全绿。
