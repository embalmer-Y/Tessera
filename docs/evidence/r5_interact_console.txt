## 3. F3 终端确认/拒绝 E2E —— 受阻登记（两项独立因素）

部署链本身工作（lease → upload 1454/1454B over TLS ✓），但：
  a) **atkbench DRAM 预算不足（本批核心发现）**：shell/log 静态面 ~3.9KB
     挤占后，系统池运行期余量不足以覆盖 WiFi TX 突发——部署高压期实测：
       <err> esp32_wifi_adapter: memory allocation failed
       <err> esp32_wifi: Failed to send packet: -105
     → WiFi 发送丢包 → TLS 掉线 → 部署流中断。池回撤实验三档：
       50048（静态紧贴）/ 56320 / 58368——58368 = TLS 建链实证下限
       （50048/56320 实测 z_open rc=-80 Z_ENOMEM 循环〔R1 grace 保活，
       零复位——R1 修复跨场景再证〕）；58368 + shell 面 = WiFi 突发
       ENOMEM。**净缺口 ≈ 8KB 静态 DRAM，需 map 驱动系统性重平**。
  b) CH343 USB 重枚举第三次复发（负载期设备掉枚举——hub/线缆域既有登记），
     console 判据窗中断；by-id 稳定路径仅解决设备号漂移，不掉枚举。
