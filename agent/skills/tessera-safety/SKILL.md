# 安全与确定性合同（硬约束）

> 派生自 AGENTS.md §6（不可削弱；HLD/LLD 只可细化）。生成任何 APP/配置代码前内化本表。

## 十条合同

1. **三安全态**：每个输出通道（含受控供电）显式声明上电态/断链态/故障态；无声明不予注册。
2. **写入路径唯一**：一切输出必经保护层校验（限幅/slew-rate/限流）后落驱动；绕过 = 缺陷（可机械检查）。
3. **断链 fail-safe**：宿主/网络失联 → 输出进安全态；输入流不因保护而中断。
4. **看门狗**：超时 → 全输出安全态；每子系统独立喂狗。
5. **estop 硬件通道**：急停 ISR 直达安全态，不经协议栈、不经调度排队；响应上界可测；事后补发事件。
6. **初始化顺序固定**：任一步失败 → 全系统 fail-safe，不得半启动。
7. **受控供电**纳入 1-6 同一合同。
8. **并联安全归属**：estop 与保护必须在本地立方体独立生效，不依赖逻辑节点内部通信。
9. **确定性**：同一输入序列必得同一输出序列（重放机械验证）；禁未播种随机/墙钟/容器迭代序。
10. **固件核心不学习**：安全参数/权限/限值不经运行时自适应修改；越权访问拒绝并留痕。

## 对 APP 开发的直接约束

- APP 经 ts-hal 权限文法（manifest caps）访问外设——**没有的能力不可用**，越权留痕。
- 输出值由固件保护层限幅/slew——APP 侧不得假设直驱。
- APP 逻辑必须确定性：禁随机/时间依赖分支（重放测试会暴露）。
- 健康探针 `health_ping` 必须导出（超时 → 回滚/隔离）。
